Part one · the correction

Proposals counted as jobs

You said you suspected the PO we set up to track proposals was skewing the data. It is, and worse than that — it has skewed every job count in every document we have sent you.

✕ What we were counting

A Deltek project record gets created when we decide to chase something. Our counts read those records. Across all 10,017 top-level projects in Deltek, only 2,411 have ever been billed.

Deltek already tracks this properly in a field called Stage — 179 In Pursuit, 86 Lost, 8 Did Not Pursue — and we were reading a different field that lumps all of them in with real work.

So when a document said "369 projects", it meant 369 records. The honest number is the one where money moved.

✕ The catch, stated plainly

743 of 10,017 projects — about 7% — have the architect filled in. The field exists on every project; it has been populated on a fourteenth of them. So this list is real but partial, and the older the job the likelier it is blank. Backfilling it is a decision about how much it is worth, not a technical problem.
