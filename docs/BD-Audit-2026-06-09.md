### C1: bc-ab-primes ingest overwrote 181 first-pass ProjectBrief rows (live incident, 2026-06-09)
**File / Table**: `tools\BdQueueDrainIngest\Program.cs:252-263`, `opportunities.MajorProjectEnrichment`
**Problem**: The ingest's marker detection is an exact-substring match for
`"[providerName: ProjectBriefHoning]"` only. The primes PROMPT

0 honing rows affected.
**Why critical**: First-pass research for 181 MPIs is gone from the DB, and
their freshness timestamps were bumped, so refresh logic thinks they're
current. Same hazard exists for the four first-pass sector markers
(`CommercialDeepResearch` etc.).
**Recommended fix**: (1) Recover the 181 briefs — original first-pass JSON

`description` field, and **skip loudly** (don't default to ProjectBrief)
when a honing/special kind yields no recognizable provider.

## Architectural concerns (not bugs)

- **Two org-merge mechanisms with opposite intel semantics**: BdCanonicalDedup *deletes* loser intel (regenerate-later theory); the m105-style migrations *repoint* it. Same operation, opposite data-preservation outcomes, and both lists of FK tables drift independently (C2, C5). One shared merge service (or one canonical SQL template generated from `sys.foreign_keys`) should be the only way orgs merge.
- **Default-on-miss provider resolution**: the drain ingest treats "couldn't identify the provider" as "must be first-pass" — the single decision that caused C1. Inverting to refuse-on-miss is a one-line philosophy change worth applying anywhere a classifier feeds an upsert.
- **In-band string markers as routing metadata** (`[providerName: …]` inside description) are fragile by construction; the envelope should carry a validated `_providerName` field, full stop.
- **Honing intelligence is trapped in ResultJson** (3 shapes, no extractor, no consumer) — the WPF build's generators are about to become the 4th ad-hoc parser. Define `HoningPass` v2 contract + extractor first (M3).
- **Operational state on a user Desktop**: `Desktop\Polish\*.json` + un-versioned pull scripts + Desktop-hardcoded outputs (M13). The BD-UI plan's DB-composed generators fix this; don't build any more on the Polish pattern.
- **Soft-retire without referential discipline**: retiring a row (org or MPI) currently says nothing about its children — every consolidation invents its own answer (repoint / retire / strand). A written rule ("children repoint to survivor on merge; children retire with parent on lifecycle retire") would have prevented M1/M5.
- **Migrations are not test-executed before commit** (C6 proves it). A scratch-DB replay gate (even manual) for any migration touching FK webs would catch the C2/C6 class.
- The five `*-final.json` + `.all-honed.json` shared-state files and the 14-day honing window (M11) make drain cadence load-bearing in hidden ways — encode windows as parameters, not constants.
