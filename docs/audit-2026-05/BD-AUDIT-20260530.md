```csharp
public static string NormalizeName(string input)
{
    if (string.IsNullOrWhiteSpace(input)) return string.Empty;
    return input.Trim().ToLowerInvariant()
        .Replace(" ", "", StringComparison.Ordinal)
        .Replace(".", "", StringComparison.Ordinal)
        .Replace(",", "", StringComparison.Ordinal)
```
```csharp
        .Replace("'", "", StringComparison.Ordinal)
        .Replace("-", "", StringComparison.Ordinal)
        .Replace("&", "", StringComparison.Ordinal)
        .Replace("/", "", StringComparison.Ordinal)
        .Replace("(", "", StringComparison.Ordinal)
        .Replace(")", "", StringComparison.Ordinal)
        .Replace("+", "", StringComparison.Ordinal);
```
Why this is a problem:
The resolver only removes punctuation and spacing; it does not normalize corporate suffixes, government word-order variants, or school-district forms. Specific duplicate patterns that still split include `Acme Ltd.` vs `Acme`, `SD68` vs `SD #68` vs `School District 68`, `City of Vancouver` vs `Vancouver (City of)`, and `Foo & Bar` vs `Foo and Bar`.
Suggested fix shape:
Extend normalization with token-level canonicalization before lookup/create: suffix stripping, `&`/`and` equivalence, school-district number normalization, and civic-name rewrites. Keep this logic shared between the resolver, the persisted SQL computed column, and dedup tooling so lookup and schema stay consistent.
