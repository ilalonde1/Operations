## The problem

KOR's BD intelligence is locked in 7 Word documents on Ian's Desktop +
the Org Dossier / Project Brief / Region Brief views in the WPF app.
There's no commercial-grade way for partners or BD leads to:

1. Generate a category-specific pursuit report on demand
2. See the cross-cutting URGENT call sheet in the app
3. Mark actions Done / In Progress / Dismissed and have that
   reflect in Priority Actions
4. View strategic-target relationship briefs (Graham, EllisDon)
   inline

6. Generate without depending on PowerShell + Word COM on the
   user's machine

## Design constraints

1. **Commercial grade — no half-assed**. Per Ian's standing
   feedback: "no MessageBox-as-detail, no shortcut schema
   mismatches, no Option A is faster framing. Highest standards
   and best practice always."
2. **No Word dependency**. Reports must generate on any Windows
   machine. Use DocumentFormat.OpenXml NuGet, not Word.Interop.
   Critical for KOR-APP01 cron jobs.
3. **WebView2 preview** — partners view inside the app, not
   external Word window.
4. **Reuse existing schema**. IntelAction.Status already exists
   for action tracking. No new tables except audit log.
5. **MCP integration**. Verdict queries become MCP tools so the
   AI layer answers "give me top 5 hospitals to pursue" verbally.

### Key architectural decisions

1. **OpenXml not COM**. NuGet: `DocumentFormat.OpenXml` 3.x. Generators
   are pure functions: `(category, verdict-data) -> byte[]`.
   Side-effect-free. Testable. No Word license required.

2. **HTML preview = same content, different renderer**. Both DOCX
   and HTML reads from `BdReportModel` (DTO). One model, two
   renderers.

3. **Report content lives in DB**. No `BdReport` table — generators
   compose from existing Intel* + MajorProjectEnrichment +
   CanonicalOrg + CanonicalOrgEnrichment tables. Reports become
   "live views" — re-generate gives fresh data automatically.

4. **MCP tools surface the SAME queries**. The dashboard's pursuit
   list + the AI's "give me top 5 hospitals" go through identical
   `IBdReportService.GetPursuitsByCategoryAsync()`. No drift.

5. **Action tracking writes back to existing IntelAction.Status**.
   UI lets BD leads mark Done / Dismissed / In Progress with note.
   Priority Actions on BD Dashboard already consumes
   IntelAction.Status — no UI re-wiring needed there.

6. **Honing freshness color-coded**.
   - Green: `LastRefreshAtUtc >= now - 30 days`
   - Yellow: 30-90 days
   - Red: 90+ days
   - "Refresh now" button on Red items kicks off targeted Sonnet
     drain (Phase 4 hook).

## DB schema changes

Minimal. One new table for audit log:

```sql
-- Migration 121_BdReportAuditLog.sql
CREATE TABLE opportunities.BdReportAuditLog (
    Id BIGINT IDENTITY(1,1) PRIMARY KEY,
    Category NVARCHAR(64) NOT NULL,
    Format NVARCHAR(16) NOT NULL,     -- 'docx' | 'html'
    GeneratedAtUtc DATETIMEOFFSET NOT NULL DEFAULT sysdatetimeoffset(),
    GeneratedByUser NVARCHAR(256) NOT NULL,
    RecipientEmail NVARCHAR(256) NULL,
    RecordCount INT NULL,
    Notes NVARCHAR(500) NULL
);
CREATE INDEX IX_BdReportAuditLog_GeneratedAtUtc ON opportunities.BdReportAuditLog(GeneratedAtUtc DESC);
```

No other schema changes. Reuse IntelAction.Status for action tracking.

## Acceptance criteria

A commercial-grade build means:

1. Partner opens KOR Ops app on their laptop with no Word installed
   and can generate every BD report from the BD Reports tile.
2. Generated DOCX is visually identical to current PowerShell-built
   reports (KOR brand styling, native Word headings, no HTML hacks).
3. WebView2 preview matches the DOCX content one-to-one.
4. Cross-cutting URGENT call sheet shows accurate top-12 across all
   10 sectors with live data.
5. Mark an IntelAction Done in the UI -> Priority Actions on BD
   Dashboard reflects it immediately.
6. Stale honing (>90 days) shows red indicator with "Refresh"
   button that triggers a Sonnet drain on that specific MPI.
7. MCP /ask "give me top 5 BC hospital pursuits this week" returns
   the same data as the dashboard would show.
8. Every generated report is audit-logged with generator user +
   timestamp + recipient.
9. No half-finished implementations. No "Option A is faster".
   No demo-quality shortcuts in the produced output.
