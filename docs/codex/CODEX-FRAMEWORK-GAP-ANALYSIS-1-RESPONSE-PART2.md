## Claims B5–B6

### B5 — TRUE for the inspected board-writing paths; live universal exclusivity cannot be established from files

The schema defines Evidence as free text and requires only nonempty evidence for done/dropped (`K/db/137_EveryCommitmentHasAnOwnerAndAProof.sql:30–45`). `lane_row.report()` appends the closing session's string and sets State/ClosedAtUtc directly; its only row predicate is ID and not-already-done. It checks neither DoneWhen satisfaction nor ownership, and its generated brief explicitly directs the worker to use `--state done --evidence` (`F/tools/lane_row.py:45–83`). This is an ordinary supported closure route, not merely a hypothetical custom SQL bypass.

`kor_task accept` does insert a fresh read-only judge for helper rows and refuses an invalid helper/state/return marker (`F/tools/kor_task.py:221–274`). That is a real narrower mechanism. It is **not mandatory even for helper rows**: `lane_row` has no helper exclusion. The judge receives builder Evidence immediately and cannot execute verification commands. Its writeback guard compares State and Evidence **length**, not the What/DoneWhen identity or an Evidence hash; an equal-length evidence replacement or requirement change is not detected by that guard (`:221–237`, `:265–273`).

Thus the claim correctly identifies the observed free-text completion weakness and the helper-specific exception, but should not imply that the exception protects all helper completion. I found no general board acceptance boundary in the inspected writers. I cannot certify the word “only” across unqueried live triggers, permissions or additional callers, nor assert that a particular live row was closed this way. Brain event/evidence freezing is a separate mechanism and must not be mistaken for an oversight.Commitment acceptance rule (`K/db/173_EvidenceIsFrozen.sql:11–20`, `:159–190`).

### B6 — PARTLY

The named mechanisms substantially exist. Records have types, provenance and freshness; LaneState and compaction capture persist resumable state; the board supplies shared task fields; HandoverState reads committed STATE NOW; and context gating really refuses covered non-handover tool actions at STOP (`Q/Records/RecordStore.cs:14–38`; `Q/Records/Freshness.cs:26–36`, `:127–147`; `Q/Capture/ClaudeCapture.cs:111–128`; `Q/Start/ModuleState.cs:256–305`; `K/db/137_EveryCommitmentHasAnOwnerAndAProof.sql:30–45`; `Q/Start/HandoverState.cs:36–54`; `Q/Context/ContextGuard.cs:237–264`). The source's default large-window thresholds are warning at 300,000, then every 100,000, and stop at 850,000 tokens; smaller-window models have adjusted thresholds, so 850k is not an unconditional rule for every model (`Q/Context/ContextGuard.cs:119–121`, `:159–173`). Context commands are wired in all three inspected repos (`F/.claude/settings.json:300`, `O/.claude/settings.json:275`, `K/.claude/settings.json:242`).

“Strongest area” remains an unmeasured comparative opinion. Persistence and source identity are much more concrete than the general fact/assumption and completion rules in these six sections, but they do not make stored text true or restoration mandatory. Freshness excludes semantic/dependency contradictions and session/query/run aging; missing transcript allows context execution; the guard documents text-only, measurement and handover-quality limits; StartGate is unwired (`Q/Records/Freshness.cs:33–36`; `CLI/Program.Context.cs:57–65`; `Q/Context/ContextGuard.cs:96–111`; three settings files, whole-file `start-gate` search). The optional cold proof is not a live prerequisite (`CLI/Program.StartProof.cs:9–15`). Without database/runtime inspection or a comparable outcome measure across all 17 sections, the superlative is not established.
