# Silent storeys — source-trace findings

The four files expose reporting gaps, but they do not establish which branch removed 31093-01's 111 outlines. Naming one as the proven cause would repeat the unverified attribution the task warns against. No source files were changed; no build or tests were run.

For **31093-01 L2**, the count's origin matters. The service initially records `geometry.Slabs.Count` after classification at `Kor.Operations.EngineeringTools.Core/Dxf/DxfToEtabsService.cs:1616`. However, the final sheet table overwrites that count with floor objects attributed to the sheet at `Kor.Operations.EngineeringTools.Core/Dxf/DxfToEtabsService.cs:2754`. Thus “111 outlines read” cannot safely be treated as 111 raw candidates entering the slab pass. If it is the initial count, those slabs have already survived classification; if it is the final table count, it describes attributed floor objects across the sheet's storeys.

The composer's silent slab-dropping `continue` is `Kor.Operations.EngineeringTools.Core/Dxf/E2kGeometryComposer.cs:1299`: `if (placedSlabs.Holds(slabStory.Name, where)) continue;`. **That cannot alone empty L2.** The tracking collection starts empty, and a place is claimed only after support checks, immediately before writing a plate on that same storey at `Kor.Operations.EngineeringTools.Core/Dxf/E2kGeometryComposer.cs:1348`. Another relevant removal occurs before composition: whole-sheet slabs covered by part-sheet slabs are filtered out at `Kor.Operations.EngineeringTools.Core/Dxf/DxfToEtabsService.cs:2052`, while the accompanying warning incorrectly says their floor plates are kept at `Kor.Operations.EngineeringTools.Core/Dxf/DxfToEtabsService.cs:2073`. Neither branch's execution for this witness is established by the supplied evidence.

There are concrete ways to lose the explanation. Unsupported slabs are recorded, but only the first four rejected outlines receive sheet/storey identification at `Kor.Operations.EngineeringTools.Core/Dxf/E2kGeometryComposer.cs:1861`. Also, disabling floors silently skips both slab processing **and the later forwarding of classifier flags**: compare `Kor.Operations.EngineeringTools.Core/Dxf/E2kGeometryComposer.cs:1230` with `Kor.Operations.EngineeringTools.Core/Dxf/E2kGeometryComposer.cs:1517`. These are demonstrable reporting defects, not demonstrated explanations for this run.

For **the five zero-outline cases**, a separate upstream defect is possible, but zero does not prove that the slab pass received nothing. Layer routing uses layer-name patterns, not “CONCRETE OUTLINE” in the sheet title, at `Kor.Operations.EngineeringTools.Core/Dxf/StructuralPlanClassifier.cs:570`. Conversely, recognized slab linework can disappear *inside* the slab pass: an unsplit loop below `MinSlabArea` is silently excluded at `Kor.Operations.EngineeringTools.Core/Dxf/StructuralPlanClassifier.cs:1318`. Flood-fill candidates also disappear silently for insufficient area or bounding-box fill at `Kor.Operations.EngineeringTools.Core/Dxf/DxfFloodFillPlateDetector.cs:369`, and unsuccessful recovery returns an empty explanation at `Kor.Operations.EngineeringTools.Core/Dxf/DxfFloodFillPlateDetector.cs:17`. The five cases therefore cannot yet be assigned one common earlier failure.

For **per-sheet fallback gating**, the proposed small-ring example is incomplete. Before the zero-count gates, `Kor.Operations.EngineeringTools.Core/Dxf/StructuralPlanClassifier.cs:1678` already checks existing slabs against a larger enclosing wall ring. When its containment and column-coverage checks pass, it clears those slabs so the perimeter fallback can run. Also, one sheet closing a ring does not make its sibling sheets' individual counts nonzero.

The genuine limitation is that this enclosure comparison sees only one sheet's walls and slabs. A perimeter assembled from several sheets is unavailable there, and downstream rejection can invalidate the earlier “has slabs” decision. A storey-level reconciliation would need to revisit the decision currently made at `Kor.Operations.EngineeringTools.Core/Dxf/StructuralPlanClassifier.cs:1678` and the fallback gates at `Kor.Operations.EngineeringTools.Core/Dxf/StructuralPlanClassifier.cs:1705` and `Kor.Operations.EngineeringTools.Core/Dxf/StructuralPlanClassifier.cs:1745`, using combined geometry and the surviving plates. Merely replacing `Slabs.Count == 0` with a storey-wide count would still accept a wrong small ring. **The source supports that architectural limitation; it does not prove that it caused these nine cases or justify widening the fallback.**
