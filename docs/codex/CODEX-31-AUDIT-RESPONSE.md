**F1 — Naming the output differently can bypass the engineer's banked join restriction. High impact.**

Contradicted sentence: “where she banked which storeys to join, those and only those join” (`PI:1188`). `Core/Dxf/DxfToEtabsService.cs:829` takes the job from the output basename; `:843` selects rows by substring containment. At `:875`, no matching rows now means every file is joinable. There is no distinction between an unknown job and a known job whose identifier disappeared from the output name.

Smallest input: two opposite-side LEVEL 1 sheets with matching seams and the stated `match-line-join.31168.<parkade>` rows loaded. Output `out-pdf-only.e2k` matches no 31168 rows, so LEVEL 1 can join despite the quoted restriction. Output `31168-C.e2k` **does** contain `31168`; it retains the restriction. Before this change, the mismatched name produced an empty joinable list and no joins. The new normal join message can describe the result, but nothing diagnoses the ignored job restriction. The same generic basename occurs as `out.e2k` in `docs/etabs-handoff/pdf_only_all.sh:11`. Although that probe passes no explicit `--rules-db`, the CLI sets `RequireRuleSettings=true` (`CLI:1962`) and loads its connection from the environment when the argument is absent (`Core/Dxf/RuleSettings.cs:87`). Thus the generic-name bypass applies even when the probe successfully loads the banked rows; missing database configuration would instead stop model generation.

**F2 — The new seam/partner transforms mix drawing units with model units. High impact.**

Contradicted sentence: “the seams are compared on the model's grid (each through its by-name frame …) … and a partner's linework is brought into the leader's frame” (`PI:1184`). `GridAlignment.SolveByName` derives offsets after multiplying axis coordinates by `scale` (`Core/Dxf/GridAlignment.cs:305`, `:336`), so offsets are in model units. The new `InModelFrame` applies that frame directly to raw drawing-unit segments (`Core/Dxf/DxfToEtabsService.cs:1017`); `Into` does the same at `:1101`. Scaling occurs later at `:1159`. Ordinary placement correctly applies its frame after scaling (`:1344`).

Smallest input: millimetre DXFs and an inch model, leader grid X=0, partner's corresponding grid X=2540 mm, with sufficient additional named axes for a fit. The partner's correct offset is −100 inches. A seam on that grid becomes X=2440 in the raw millimetre coordinates used for grouping, rather than X=0. That exceeds the 152.4 mm seam tolerance. If sheets nevertheless group, their partner linework inherits the same offset-unit error. The PDF-only mm-to-mm probe has `scale=1`, so it cannot expose this fault. The pre-change union did not contain this particular transform error; it also could not correctly register arbitrary PDF page frames.

The “fit's own tolerance, 6 inches” wording (`PI:1185`) also mixes conventions: the solver compares model-unit offsets with the fixed numeric `NameTolerance=6` (`GridAlignment.cs:232`, `:343`), while the new seam tolerance divides that six by inches-per-drawing-unit (`DxfToEtabsService.cs:1029`). With a millimetre model and drawings, the fit's vote-cluster reach is 6 mm and the seam tolerance is 152.4 mm. They are not the same physical tolerance.

**F3 — Overlap joins admit multiple and unrelated partners; Revit behavior is expanded too. High impact.**

Contradicted sentence: “a Revit export, one frame for every sheet, is joined exactly as before” (`PI:1188`). `Core/Dxf/MatchLineSheetJoin.cs:22` adds a provider-independent overlap branch. `Group` compares each candidate with the leader, adds every qualifying opposite-side sheet, and does not require partners to agree with one another or share a building/neighbour identity (`:124`).

Smallest input at the default tolerance 12: same-storey seams A=(0,0)–(1000,0), B=(100,0)–(600,0), C=(400,0)–(900,0). Put A's structural endpoints above the seam and B's and C's below. Both B and C are added to A. Previously neither endpoint pair matched A. `DominantSide` rejects a sheet that straddles the seam or lies on the same signed side; it does not establish that B and C are the intended neighbours. Already identical endpoint seams could already form such a group before this commit: the regression is the newly admitted unequal extents, not the existence of arbitrary-sized groups itself.

There is also a direction qualification to “whichever way round they were drawn” (`:17`): `SameAs` handles reversal, but `Group` compares side signs calculated against each sheet's *own* oriented seam (`:120`, `:131`). Reverse B's endpoints while leaving its structure below the same physical line; its side sign flips and the valid join can be refused. This sign defect predates step 22; the new branch does not guard against it.

**F4 — `pdf-levels` does not always keep the first stated duplicate. High impact.**

Contradicted sentence: “the first stated is kept and the rest reported” (`PI:1120`; also CLI output at `CLI:236`). `plHeights` records the first row (`CLI:215`) but only its keys are used to find bases. The chaining loop traverses the original, non-deduplicated table (`:223`), taking the first row whose lower level is reachable before the destination has been assigned.

Smallest input table, in this order, with heights in mm: `(L2,L1,3000)`, `(L2,P1,9000)`, `(L1,P1,4000)`. P1 starts at zero. The first row cannot chain yet; the second sets L2=9000; the third sets L1=4000. Subsequent passes never replace L2 with the first statement's 7000. The console still says “first stated kept.” This table can come from a stick file placing one building's L2 elevation before another building's L2 and the common lower-storey elevation later. Subsequent levels chained above L2 inherit the selected value. `SetStoreys.Reconcile` preserves first-seen pair order (`Core/Intake/SetStoreys.cs:65`).

**F5 — The grid seed is unvalidated, and its origin note is normally erased. High impact when grid names repeat.**

Contradicted/overbroad sentences: “the drawings' own reference plan is the grid” and “the sheet naming the most axes stays in its frame” (`PI:1195`, `:1198`). Selection counts named axes, not distinct authoritative grid names, plan suitability, building identity or model placement (`Core/Dxf/DxfToEtabsService.cs:957`). It accepts even three axes of one orientation; the usual by-name solver requires matches on both orientations (`Core/Dxf/GridAlignment.cs:307`).

Smallest ambiguous set: a key plan carries two translated copies of the same three-name grid, with two X names and one Y name, for two identical buildings. It has more axes than either building's floor sheet. An isolated floor sheet with those three names can fit either copy with zero residual. `AgreedOffset` breaks equal label/vote ties by the smaller move (`Core/Dxf/GridAlignment.cs:343`). Thus the fits agree on a copy chosen partly by page position, not on building identity. A differently scaled site plan can instead cause the other fits to fail; a site plan is not automatically wrong if its coordinates and identities are sound.

The seed gets an explicit “reference plan … no model grid” note at `Core/Dxf/DxfToEtabsService.cs:963`. But the next loop includes that very sheet and overwrites its `Fit` when solving against the grid just copied from itself (`:970`). Three distinct axes split across both directions suffice. The report at `:1001` then prints an ordinary zero-residual by-name fit. The special note survives only where this self-fit fails; there is no persistent seed-origin flag.

A crossing at one point can therefore suppress an otherwise independent full wall. Sorting by overlap and then gap (`:640`) leaves exact ties in input-pair order.

Smallest face construction: establish a cut pen using the remote filled-wall fixture, then use four same-pen segments in mm: horizontal faces (7000,9850)–(13000,9850) and (7000,10150)–(13000,10150); vertical faces (9850,7000)–(9850,13000) and (10150,7000)–(10150,13000). Horizontal-first yields only the horizontal wall; vertical-first yields only the vertical wall. Each rejected midpoint lies in the first accepted wall, although most of the rejected wall does not.

`TwoFaceLinesAWallsThicknessApartAreAWallTests` has shared-face and stub examples (`:241`, `:253`), but no permutation or intersecting-pair assertion. Its existing checks do not exercise this case. Separately, §28's “taking the nearest such partner” (`PI:1019`) is superseded by longest-overlap-first in §29 and the code: “nearest” is not the implemented primary ordering.

**F7 — Accepted face lines can lose their unconsumed drawing, and tapered walls are rectangularized.**

Qualified sentence: “The wall is the overlap, its thickness the gap; both lines are read as its faces … writes the wall and not the faces as beams” (`PI:1026`). The implementation maps each *whole* source line to one wall (`Core/PdfToSafe/GeometryFilterService.cs:754`), and the exporter suppresses the whole line (`Core/PdfToSafe/DxfExporter.cs:137`). No residual segment represents the portion outside the overlap.

Smallest input: one 6000 mm outer face and two disjoint, wall-length inner-face segments at 300 mm separation, the first longer than the second. The longer pier wins; the whole outer face is marked Read and omitted from BEAM; the other inner face stays a line. The lost second pier is explicitly acknowledged in `PI:1102` and the shared-face test, so this is a documented limitation, not an undisclosed claim that both piers work. The ledger's whole-path Read credit does not mean its whole length became a wall.

For tapering, the outline at `GeometryFilterService.cs:744` is a rectangle parallel to the first face, offset by the mean of the second face's *full endpoint* offsets. A 6000 mm face at y=0 paired with (0,300)–(6000,400) passes the taper check but emits a rectangle at y=0..350, not the drawn trapezoid. If faces overlap only partly, even taper qualification and the mean use endpoints beyond the overlap (`:573`). This is a geometry approximation beyond merely recognizing that faces may converge.

**F8 — The Band rule rejects genuine narrow floors.**

Overbroad sentence: “a filled band thicker than the thickest wall … is a band … not a slab” (`PI:1078`). The predicate only knows the oriented bounding box, fill/annotation status, paper colour and configured maximum wall thickness (`Core/PdfToSafe/GeometryFilterService.cs:323`). Smallest input: a non-paper, closed filled rectangle representing a 66-inch-wide, 800-inch-long corridor slab or balcony run, outside furniture and not a declared column. With the defaults, 66 > 60.5, 66 <= 120 and aspect > 10. The rule applies to this legitimate floor just as it applies to 31168's grey strip.

**F9 — The raster does not deliver an exact outer face or an exact doorway limit.**

Contradicted sentences: “the closing adds no width … its boundary is the outer face” (`PI:1165`) and, as an exact cutoff, “gaps up to a doorway” (`:1163`). Paint includes samples inside the rectangle or within 0.75 pixel of an edge; cell boundaries are then traced from integer coordinates to coordinate+1 (`Core/Dxf/DxfFloodFillPlateDetector.cs:91`, `:411`). Dilation and erosion do not undo that initial sampling/cell convention. Simplification and straightening add further approximation (`:133`).

Smallest aligned example: the tests' 1200 by 720 inch outer rectangle, with the default 6-inch pixel. Samples include its boundary; traced cells can extend the high-coordinate boundary to 1206 and 726. The rectangle test expressly allows a six-inch deviation and 2% area error (`Tests/Dxf/AStoreysPlateIsWhatItsWallsEncloseTests.cs:45`). Thus the reported 0.4% and 0.7% end-to-end agreements include whatever raster bias those outputs contain; there is no pixel-bias correction or decomposition proving exact agreement of vector outer faces. The numbers themselves were not remeasured.

The radius is `ceil(max(MaxOpeningSpan,FloodFillBridge)/(2*pixel))`, at least one, and dilation uses a square, not a Euclidean disc (`:69`, `:73`, `:102`). In the axis-aligned test ring an exactly 72-inch opening closes: it spans 12 six-inch intervals and each end grows by six cells. The tests use 48 and 120 inches, never the 72-inch boundary. Quantization, orientation and the maximum of two settings govern the actual cutoff; some gaps wider than the advertised doorway can close. “Outer face plus up to one pixel” describes the simple aligned example, not a rigorous global error bound for rotated edges, tolerance paint and straightened corners.

**F10 — The leak/coverage checks do not prove that the outer perimeter closed.**

Smallest construction: use the tests' 1200 by 720 inch ring, put a 120-inch opening in the south wall centred at x=900, and add a full-height divider at x=600. Six panels suffice (the south wall is two). The right-hand perimeter leaks, but the left compartment encloses about 432,000 square inches. The stronger sentence “a ring … over few … columns is a core, not the floor” (`PI:1202`) also omits that the gate runs only for four or more columns and only for the new panel route. A large concentric ring already in `EnclosedByWalls` prevents that route from running (`:1476`).

**F11 — Match-line discovery can lose or invent a seam; diagnostics do not fully explain why.**

Qualified sentence: “reads the words MATCH LINE … and the line spanning at least 40% of the page beside them” (`PI:1177`). `Core/PdfToSafe/SheetFurniture.cs:114` rounds perpendicular coordinates to integer points and stores only each bucket's min/max extent. Smallest missed seam: on a 1000-point-wide page, dash pieces cover x=100..350 at y=500 and x=350..600 at y=501, with a horizontal MATCHLINE label nearby. `pdf-overlay` prints zero match lines and that MATCH appears but no spanning line runs beside it (`CLI:770`); it does not identify a rounding split. Without a detected/exported seam, the ETABS unjoined-seam warning cannot fire (`Core/Dxf/DxfToEtabsService.cs:1042`). The constituent paths retain whichever ordinary fates they reach. They are not necessarily all beams: grid, furniture, short-line and other rules still precede or replace line emission.

**Answers to the thirteen questions, in order**

**1. The wall and the cut pen.** A pilastered wall with one continuous face loses its second pier (F7); a face coincident with a recognized grid axis is removed before pairing (`GeometryFilterService.cs:215`); mixed cut/light faces fail the two-cut-lines requirement (`:610`). A non-wall accepted besides the documented curb is an unfilled long coping/ledge or deck-edge band with two cut-pen edges 300 mm apart and 6000 mm long, no intervening pattern or risers, and the remote filled wall needed to establish the pen. A stair drawn with only two qualifying risers is another admitted input. These are counterexamples to the drawing convention, not claims that the five sets contain them.

`CutPen` counts exact width values returned by `FilledWallFaceLines`, chooses the largest group, and breaks equal counts toward the **wider** pen (`GeometryFilterService.cs:518`). It does not choose by total face length or a separate cut-wall type. Two equally represented pens 0.5 and 0.9 pick 0.9; cut walls whose two faces use 0.5 then fail. More frequent 0.5 picks 0.5 instead. Nothing establishes which mode describes all cut walls. Even a filled wall is insufficient unless separately emitted two-point face strokes satisfy the near-edge/full-containment and greater-than-half-edge-length tests (`:477`). No qualifying face stroke means zero cut pen and no inferred face walls.

**2. Order dependence.** F6 gives four distinct face lines and two equal-length/equal-gap candidates. Permuting the horizontal and vertical pairs changes the retained wall. The listed tests would not notice. The unequal shared-face example in the existing tests checks the deliberately preferred longest overlap, not invariance under arbitrary path order or intersections.

**3. Band.** F8 gives the real-floor counterexample and exact ledger outcome. Annotation paths cannot reach Band: `obox` excludes annotations (`GeometryFilterService.cs:249`), and the predicate separately requires `!IsAnnotation` (`:323`). That is consistent with the repository's stated markup semantics—annotations are the user's structural input (`:190`)—so making Band suppress a drawn slab annotation would contradict that route. The exact lower bound includes half an inch of slack, not simply anything over 60 inches. The upper limit is inclusive at 120 inches; the tests use 121 rather than checking equality.

**4. Plate.** (a) The ordinary aligned 72-inch boundary closes; 48-inch-close and 120-inch-open fixtures do not test equality or immediately adjacent values (F9). (b) It is a raster-derived approximation with a one-cell excess in the aligned example, not an exact face; the §31 comparisons include that approximation. (c) `LoopGeometry.PointInPolygon` has a strict ray crossing and no boundary-distance policy (`Core/Dxf/LoopGeometry.cs:68`). For a rectangle, a centre on the left/bottom boundary can be counted while one on the right/top is excluded. With four columns—two definitely inside and one on each vertical boundary—3/4 can become 2/4 under a tiny outward shift, crossing the 0.6 threshold. A column on the *wall centreline* is normally half a wall thickness inside the *outer* plate and is not inherently on the polygon boundary; instability applies where its centre coincides with the recovered boundary or sampling/straightening moves that boundary onto it. (d) F10's divided, leaking ring passes the area heuristic.

The detector is called even for a foundation sheet. The later classifier branch with `sheet.IsFoundation` prevents adding its result to `Slabs` (`StructuralPlanClassifier.cs:1525`). Therefore “never on a FOUNDATION sheet” is true of fallback floor emission, not of running the detector. Existing slab edges block it only after they have produced a retained slab; merely present open edges do not block it. A null sheet descriptor supplies no foundation protection. Failure diagnostics try bridges at 2, 4 and 8 times the doorway (`:1502`), so “at what gap it would have” reports a coarse successful trial, not a measured widest gap. A 100-inch gap can be described by a 144-inch trial.

**5. Match-line detection.** (a) A single 6-by-48-point MATCHLINE takes the immediate single-token branch: vertical orientation, 6-point text height, 36-point seam reach. The `Math.Max` value is used to find a separate LINE token only for MATCH. A square word takes horizontal orientation because `Height > Width` is false; the code has no ambiguous-orientation state. (b) Two separately selected, spatially distinct seams survive `found`; duplicate selections of the same normalized bucket extent collapse (`SheetFurniture.cs:140`). `IsOnMatchLine` loops over both. There is no inherent two-label deduplication failure. Two labels can nevertheless select the same nearest line; no one-to-one label assignment prevents that. MatchLine fate also loses to preceding furniture/grid/underline checks (`GeometryFilterService.cs:209`). A seam exactly on a named grid can be exported as a seam while its strokes are fated GridAxis. Downstream, `SeamOf` retains only the longest MATCH-layer segment (`MatchLineSheetJoin.cs:69`), so retaining two PDF seams does not enable a two-seam join. (c) F11 gives the split-bucket condition and the actual overlay/ETABS diagnostics.

**6. Seams as lines.** F3 gives the newly admitted group of three, the unchanged identical-endpoint case, and why `DominantSide` is necessary but insufficient. Grouping tests only a nonempty storey intersection (`MatchLineSheetJoin.cs:128`), not equality of complete storey sets. The new `SameAs` branch also measures both of the other's endpoints against the leader's line, not symmetrically against both infinite lines; with nonzero tolerance and very different lengths, approximate matching need not be symmetric. The three-sheet case does not require that extra numerical issue.

**7. Joinable sheets.** `out-pdf-only.e2k` misses the `31168` substring; `31168-C.e2k` matches it. WITH matching rows, the parkade-only restriction still applies to both site and C-named outputs. WITH the database but a generic basename, the changed empty-row fallback silently broadens eligibility to every sheet; before step 22 it disabled joining. See F1. The quoted migration ruling was taken as given; no external migration file or database was read. The row selector uses key names, not their values (`DxfToEtabsService.cs:840`); this analysis assumes the positive parkade rows described in the brief, not an unseen explicit false row.

**8. Seeded grid.** F5 supplies the wrong-key-plan set and explains what the fits agree on. The seed is a convention about which source to trust; a zero-residual self-fit is not independent evidence for it. The initially distinguishable note normally becomes indistinguishable from an ordinary fit because it is overwritten. An explicit offset prevents seeding; too few named axes leaves no seed; not every other sheet is guaranteed to fit.

**9. `Unapply`.** The inverse algebra is correct for rotation followed by translation: subtract offsets, then multiply by the transposed rotation matrix (`DxfToEtabsService.cs:1023`). It does not share `Frame.Apply`'s exact quarter-turn constants (`Core/Dxf/AnnotationOverlay.cs:51`). With frame (90°,0,0), point (1,0) maps exactly to (0,1), then inversely to approximately (1,6.12e−17), not (1,0).

That does **not** by itself prove that a closed, isolated partner outline opens: both copies of an identical partner endpoint undergo the same deterministic arithmetic and remain identical to each other. The downstream builder uses exact *quantized node identity*, with `Round(coordinate / joinTolerance)`, and closes on node IDs (`Core/Dxf/PlanLoopBuilder.cs:42`, `:99`), rather than requiring raw double equality for every endpoint. Transformed versus untouched endpoints near a rounding boundary can split nodes, and slight direction changes can affect junction choices (`:143`); those are qualified numerical risks. The comment in `AnnotationOverlay` is not sufficient evidence to assert that every quarter-turned partner ring loses closure. No executed closure failure is claimed here. F2 is the separate, much larger unit error in the same new transform path.

**10. `pdf-levels`.** Two buildings sharing L2 at different elevations, or an older elevation sheet appearing before its revision, make “first stated” an unsuitable authority rule. The model gets one name/elevation rather than both buildings' storeys; downstream heights inherit it. Repeated *identical (level, below) pairs* are already combined by median before this CLI step (`SetStoreys.cs:73`), so not every repeated printed name reaches the CLI as two rows. F4 shows that even the stated first-row policy is not consistently implemented.

Every unparented root gets zero (`CLI:217`), so two disconnected ladders also lose their relative datum; “lowest stated level” is really “each graph root,” not an absolute-elevation comparison. The CSV **does** record mm in a comment (`CLI:227`). `E2kShellBuilder.ParseLevels` strips comments (`Core/Dxf/E2kShellBuilder.cs:50`) and does not consume that unit. Without `--levels-unit`, `dxf-to-etabs` defaults to inches (`CLI:1857`; request default at `DxfToEtabsService.cs:47`). A CSV value 3000 is consequently 3000 inches rather than 3000 mm. The documented example and probe explicitly pass mm; the generated file is not self-configuring.

**11. Trace hooks.** Repository-wide C# references show the CLI is the sole setter (`CLI:665`). Its `PdfPlanReader.Read` call is itself a production reader and observes the static field while set. Any other concurrent classifier call in that *same process* would also observe it; a separately running WPF process does not share the field. Clearing occurs only on normal return, not in a `finally` (`CLI:667`), so an exception in a reused process could leave it installed.
