# Architecture Map Re-Audit Response

Scope: commit `fcbe7ce4` only. I did not run `dotnet build`, `dotnet test`, or regenerate `docs/architecture/architecture.json`.

## Ship-Blocker

CRITICAL: The new staleness gate can pass the same wrong source ownership model the extractor writes. The extractor counts source ownership from a physical `*.cs` walk plus nearest project-directory prefix at `Kor.Operations.Architecture/Program.cs:406` and `Kor.Operations.Architecture/Program.cs:539`, then only adds non-glob `Compile Include` links at `Kor.Operations.Architecture/Program.cs:554` with wildcard includes skipped at `Kor.Operations.Architecture/Program.cs:560`. It never applies `Compile Remove`; `SkipSource` only filters generated/bin-style paths at `Kor.Operations.Architecture/Program.cs:581`. The gate copies the same shape: physical source walk at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:154`, nearest prefix ownership at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:160`, non-glob `Compile Include` only at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:171`, wildcard skip at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:177`, and the same generated/bin-only skip at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:231`.

Trigger: a project with `<Compile Remove="Generated\**\*.cs" />`, a project using `<Compile Include="..\Shared\**\*.cs" />`, or a repo-root `App.csproj` with `Program.cs`. The root case is especially direct because a root project dir becomes `"."` at `Kor.Operations.Architecture/Program.cs:441`, then `Program.cs` does not start with `"./"` at `Kor.Operations.Architecture/Program.cs:539`; the copied gate gets the same `"."` from `ProjectDir` at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:222` and makes the same prefix check at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:160`. Current repo already has real `Compile Remove` patterns in `Kor.Operations.App/Kor.Operations.App.csproj:293` and `Kor.Operations.App/Kor.Operations.App.csproj:301`.

Consequence: the committed map can claim a project compiles files or types it does not compile, omit files compiled through wildcard includes, or mark root-level compiled source as loose, and the "map is current" test still passes because it repeats the extractor's approximation rather than checking the MSBuild compile item set.

## Findings

CRITICAL: `Relationships` still crashes when there are no project nodes. It creates project nodes from `projects` at `Kor.Operations.Architecture/Graphs.cs:48` and external nodes at `Kor.Operations.Architecture/Graphs.cs:50`, but computes `maxProject` with `.Max()` over `nodes.Where(n => n.Group != "external")` at `Kor.Operations.Architecture/Graphs.cs:96` without `DefaultIfEmpty`. Trigger: an empty repository, a repository with only loose `.cs` files, or a repository whose only project is excluded as an architecture-tool path. Consequence: extraction crashes before it can emit even an empty relationships graph.

MATERIAL: External-system edges are still assigned by physical file location, not by compile ownership. The extractor detects external hits once per physical file before walking owners at `Kor.Operations.Architecture/Program.cs:259`, while type/format ownership is per owner at `Kor.Operations.Architecture/Program.cs:294` and `Kor.Operations.Architecture/Program.cs:311`. The relationships graph later maps external evidence back to a project by nearest project-directory prefix at `Kor.Operations.Architecture/Graphs.cs:63` and `Kor.Operations.Architecture/Graphs.cs:66`. Trigger: `App.csproj` links `..\Shared\DeltekClient.cs`, and that linked file contains a Deltek marker. Consequence: `App` gets the type and format ownership, but the outside-system tie is credited only to the physical `Shared` project or to nobody, so the relationships page underreports the project that actually compiles the dependency.

MATERIAL: The test-type format filter can still count test-project handlers when a test project compiles a production-named linked file. Types are created per compiling owner at `Kor.Operations.Architecture/Program.cs:294`, but their role is derived from `Roles.For(name, rel)` at `Kor.Operations.Architecture/Program.cs:299`, not from `projectName`. Formats are emitted against each owner at `Kor.Operations.Architecture/Program.cs:311`. The renderer excludes only roles equal to `"test"` at `Kor.Operations.Architecture/VisioRenderer.cs:528` and `Kor.Operations.Architecture/VisioRenderer.cs:530`. Trigger: `App.Tests.csproj` includes `..\App\PdfReader.cs`; the created `App.Tests:...PdfReader` type has a production `read` role because the file/name are production-shaped. Consequence: the format matrix and master sheet can show a test project as a non-test `.pdf` handler.

MATERIAL: UTF-16 source files are silently misread. The extractor reads every source through `TextFiles.ReadAllText` at `Kor.Operations.Architecture/Program.cs:251`, then parses that text with Roslyn at `Kor.Operations.Architecture/Program.cs:266`. `TextFiles.ReadAllText` tries strict UTF-8 and otherwise falls back to Latin-1 at `Kor.Operations.Architecture/Program.cs:833` and `Kor.Operations.Architecture/Program.cs:839`. Trigger: a valid C# file saved as UTF-16 LE with BOM. The compiler can read it, strict UTF-8 rejects it, and Latin-1 turns it into gibberish. Consequence: valid compiled types, format edges, and external markers can disappear from the model. The new decoding test covers only a Latin-1 `.txt` file at `Kor.Operations.Architecture.Tests/ExtractorTests.cs:320` and `Kor.Operations.Architecture.Tests/ExtractorTests.cs:323`, not compiler-compatible source encodings.

MATERIAL: The architecture-tool exclusion overmatches future real projects. `IsArchitectureToolPath` takes the first path segment and excludes anything whose first segment starts with `Kor.Operations.Architecture` at `Kor.Operations.Architecture/Program.cs:589` and `Kor.Operations.Architecture/Program.cs:593`; the gate duplicates that predicate at `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:239` and `Kor.Operations.App/Kor.Transmittals.App.Tests/ArchitectureMapIsCurrentTests.cs:243`. Trigger: a real project named `Kor.Operations.ArchitectureReports` or `Kor.Operations.ArchitectureClient`. Consequence: the project, its sources, and its references disappear from both the extractor and the staleness gate.

## What Input Would Break This That Nobody Has Tried

1. `C:\temp\rootmap\App.csproj` plus `C:\temp\rootmap\Program.cs`: root-level source is treated as `(loose)`.
2. `App/App.csproj` with `<Compile Remove="Generated\**\*.cs" />` and `App/Generated/Old.cs`: removed code is counted and parsed as compiled.
3. `App/App.csproj` with `<Compile Include="..\Shared\**\*.cs" />`: linked compiled files are skipped by both extractor and gate.
4. `App.Tests/App.Tests.csproj` with `<Compile Include="..\App\PdfReader.cs" />`: a test-owned handler can show up as a production format handler.
5. A repo with no non-architecture projects: `Relationships` throws on `.Max()`.
6. `App/Utf16Thing.cs` saved as UTF-16 LE with BOM: compiler-valid code is decoded as Latin-1 garbage.

## What Looks Right

The partial-type aggregation itself is directionally solid for the covered cases: files are accumulated per stable path/span order before the final `ArchType`, and the new shared-linked-source duplicate test at `Kor.Operations.Architecture.Tests/ExtractorTests.cs:220` targets a real false-positive class from the first fix pass.
