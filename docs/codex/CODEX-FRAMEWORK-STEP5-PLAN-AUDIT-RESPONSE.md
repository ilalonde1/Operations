### What files alone can and cannot establish

- **Offline, given complete trustworthy records:** case completion/eigenvalues, numerical results, mesh coverage/connectivity, load accounting, hash identity, import/export differences, CAD comparison calculations and contradictions in documentation can be rechecked. Files must include the relevant raw source, actual application exports and run logs, not just the builder's PASS CSV. - **Requires the target application or a trustworthy captured run:** whether a new binary really imports/opens/saves in the named version, displays a dialog, finishes meshing/solving, or produces the exported content. A hash authenticates identity only relative to trusted evidence. The current D3 chain expressly excludes screen dialogs (`S/check8/scripts/d3_chain.py:1–3`). - **Requires runtime observation:** solver-child cleanup, concurrent-run ownership and behavior on cancellation/crash. C22 cannot be certified from a completed LOG; `R3:80` and `R4:137` explicitly identify that limitation.
- **Requires independent visual/engineering judgement:** whole deflected-shape review, source interpretation where CAD carries no relevant use annotation, engineering acceptance of anomalies, and causal load-transfer assertions not measured by the exports.
