# NetworkOps endpoint agent audit

Static review of the specified files at HEAD only; no builds, tests, network access or SQL. Paths below are relative to the named NetworkOps project. Findings are source-derived, not reproduced.

## Critical

**1. Pre-created descendants bypass the script-directory protection (trust).** `Transport/RemoteAgentInstall.cs:45`, `Agent/DataFolder.cs:17`, `Agent/AgentLoop.cs:162`. Before installation, an ordinary user able to create the ProgramData hierarchy can pre-create `Agent\work` with a protected DACL granting themselves write access. Both securing routines replace only the ancestor's DACL; neither rejects existing descendants or resets their protected/explicit permissions. Creating `work` again preserves it. The user can then replace a dispatched `.ps1` between write and PowerShell opening it, obtaining SYSTEM execution. Setting the ancestor owner at agent startup does not repair descendants. A similarly pre-created key file can retain explicit access. **Smallest fix:** reject reparse points and unexpected pre-existing trees; establish trusted ownership and exact ACLs on the data directory, work directory and key before writing secrets or launching scripts. Do not rely on inheritance to sanitize an existing tree.

## Material

**2. Cancellation leaves an unclaimed job executable (exactly once).** `Service/Agents/AgentHub.cs:115`, `:123`, `:158`. Enqueue a job, cancel its caller before pickup, then allow an already-held poll to dequeue it. `WithinAsync` throws; `finally` removes only `_jobs`, leaving `Claimed == 0` in the channel. The poll claims and returns a script whose caller has already abandoned it; its result gets 404. **Fix:** atomically withdraw unclaimed jobs on every exit, including cancellation. Claimed jobs also need explicit cancellation/deadline semantics if callers must prevent subsequent execution.

**3. Stopping the agent leaves SYSTEM PowerShell running.** `Agent/AgentLoop.cs:64`, `:173`, `:184`, `:198`; `Agent/Program.cs:85`. During a repair, stop/upgrade/remove the service. Cancellation throws out of the wait, bypassing `KillTree`; disposing `Process` does not terminate it. Shutdown waits only for polling, not job tasks. The old repair can continue through removal or overlap a replacement job, while startup deletes its files. APP01 restart similarly loses pending results while endpoint jobs continue. **Fix:** track job tasks, kill and await process trees on cancellation, and join jobs during shutdown; use a kill-on-close Windows job object for crash containment. Persist/reconcile execution state before treating a lost job as safe to repeat.

**4. Concurrent installs can strand the agent with the wrong key.** `Service/Sweep/ActionRunner.cs:39`, `Service/Agents/AgentRollout.cs:37`, `Transport/RemoteAgentInstall.cs:48`, `:54`. A manual action and rollout can install the same PC concurrently. A writes key A; B writes key B and saves hash B; A saves hash A. The service starts with B and is refused indefinitely. An overlapping removal can revoke/delete a new installation. **Fix:** one per-device lock shared by manual installation, removal and rollout, covering remote mutation, credential update and confirmation. Reinstallation otherwise repairs this state.

**5. Installation can report success without the new agent calling in.** `Service/Agents/AgentInstaller.cs:44`, `:52`; `Service/Agents/AgentHub.cs:94`. An old poll is held when upgrade begins. Stopping the old service cancels it; the poll's `finally` advances `LastPollUtc`. Installation starts a new agent that never successfully polls. The changed timestamp still satisfies confirmation, so rollout proceeds. **Fix:** confirm an authenticated poll under the newly saved credential generation, after activation, with the expected version; poll completion is not fresh authentication.

**6. Revocation does not revoke a held poll.** `Service/Agents/AgentApi.cs:46`, `:68`; `Service/Agents/AgentInstaller.cs:35`. Authenticate a poll, then remove/replace the credential while it waits. Authentication is never revisited, and the hub is not invalidated. That old request can still receive a subsequently queued script during its remaining hold. New requests with the old key are correctly refused. **Fix:** bind connections/jobs to credential generations and cancel/invalidate held polls and queued work on rotation/removal.

**7. Installer partial failures can become invisible to rollout.** `Transport/RemoteAgentInstall.cs:43`, `:48`, `:52`, `:54`, `:59`; `Service/Store/NetworkOpsStore.Agents.cs:117`. Failure before stopping preserves the previous state; failure after stopping leaves it stopped; failure after key replacement but before SQL save leaves mismatched credentials; partial copy leaves mixed binaries. After SQL save, SCM/create/start failure leaves a current-version row despite a nonworking agent. Rollout filters by that installed version and skips it thereafter. These exceptions normally fail the action; reinstall repairs them. **Fix:** record installation as pending and select unconfirmed/failed installations for retry, promoting version only after verified contact.

Removal first revokes SQL, then stops/deletes remotely. A remote failure leaves a revoked installation, excluded from agent findings but normally accompanied by a failed action. At `RemoteAgentInstall.cs:83`, however, the delete return code is discarded: if deletion fails but folder deletion succeeds, removal reports success with a registered service pointing at missing files. **Fix:** check deletion status and verify service disappearance; retain explicit removal-failed state.

**8. Idle collection has an unbounded pipe read and broad inheritance.** `Agent/ConsoleIdle.cs:49`, `:54`, `:70`, `:79`. The inheritance flag requests every inheritable handle, not just this pipe's writer; overlapping launches expose other inheritable writers where inheritance succeeds. The read-handle flag change is unchecked. After a successfully launched helper exits, `ReadToEnd` has no timeout: a retained writer, including one duplicated by the user controlling their helper, prevents EOF indefinitely. This occurs before the PowerShell timeout starts. **Fix:** use an explicit handle allowlist with a session-compatible IPC mechanism, check handle setup, and bound bytes/read duration/cancellation. Normal token/process cleanup is present; no SYSTEM-token inheritance exploit is established by these files.

**9. Unauthenticated traffic reaches expensive work.** `Service/Agents/AgentApi.cs:44`, `:75`, `:92`; `Service/Api/ApiHost.cs:57`. Body binding precedes in-handler authentication, allowing anonymous requests to consume the 40-MiB body budget. Any syntactically plausible name/key triggers SQL credential lookup before rejection. Parallel requests can consume API memory, connections and database capacity. Invalid keys do not enter the 25-second job hold. **Fix:** authenticate headers before body binding, impose small poll limits, and rate-limit/concurrency-limit authentication and result uploads.

**10. Endpoint concurrency is unlimited.** `Agent/AgentLoop.cs:64`; `Service/Agents/AgentHub.cs:168`. Repeated accepted actions start concurrent PowerShell processes without a per-PC ceiling; stuck idle reads compound accumulation. Ordinary process timeout bounds individual scripts, not aggregate load, and `KillTree` ignores failure. **Fix:** enforce bounded admission/concurrency before pickup, with a separate limited probe lane if repairs must not block health checks; verify termination.

**Work-directory validation misses PowerShell smart quotes (trust).** `Core/OnTarget/OnTargetPayload.cs:40`, `:58`; `Service/Agents/AgentHub.cs:55`, `:77`. Only ASCII apostrophes are rejected; PowerShell also treats U+2019 as a string delimiter. A holder of this PC's key can submit a work directory containing that delimiter, a second argument and injected statements. If the legitimate agent already has a held poll, the forged poll changes shared `WorkDir`; a subsequent job delivered to the legitimate poll can contain the injected statements. This requires that PC's credential, not merely network access, and does not cross device identities. **Fix:** accept only the fixed expected local work directory, or pass the path as encoded data rather than interpolated PowerShell source; bind it to the receiving poll instead of mutable connection state.

## Minor

**11. Rollout reverses explicit removals and cancellation leaves incomplete actions.** `Service/Store/NetworkOpsStore.Agents.cs:106`; `Service/Agents/AgentRollout.cs:38`. Removed rows become null versions and are selected again. Eligibility is a snapshot: retirement/removal after selection is not rechecked; recently reachable PCs may now be offline. Cancellation bypasses action completion. Startup attempts cleanup (`Sweep/ActionRunner.cs:25`), so this is not necessarily permanent, but cleanup failure has no retry there. **Fix:** distinguish opt-out from never-installed, revalidate before mutation, and finalize cancelled actions with bounded cleanup/reconciliation. The initial query excludes retired and non-AD/rack rows.

**12. Findings have grace/version gaps.** `Core/Health/AgentRules.cs:28`, `:33`; `Service/Agents/AgentApi.cs:63`. A newly saved row with null contact can immediately produce `agent-silent` during a successful network check; installation age is unavailable to the rule. Unsupported version strings silently suppress `agent-outdated`, while rollout repeatedly selects them. **Fix:** include installation grace and use one normalized version parser with an explicit unknown-version outcome. Normal five-minute touch lag alone does not exceed the fifteen-minute silence threshold after a short APP01 restart. Failed network checks cannot establish agent silence.

Other requested checks: default HTTPS pins the certificate and disables proxies; no direct cross-PC key/result substitution was found. Require HTTPS and disable automatic redirects explicitly to preserve that invariant across configuration changes. GUID job names and filename checks prevent ordinary traversal. Normal pickup/withdraw races are exclusive; losing a response after claim loses execution/result certainty rather than triggering automatic network duplication. Log rotation and wrapped result limits are bounded. Sleep can outlast the server's result deadline; timeout is not proof that execution did not occur.

**Exactly one ship-blocker: finding 1 — pre-existing writable descendants permit SYSTEM script replacement.**
