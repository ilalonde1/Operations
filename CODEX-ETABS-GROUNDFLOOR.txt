  Two shapes of failure, and they are not the same problem:

    - SLABEDG-2 breaks into 187 pieces with a median gap of 11 inches and 373 of 374 loose ends

  Also measured, so you do not go looking: these DXFs contain LINE and ARC entities only. No
  LWPOLYLINE, no TEXT, no MTEXT -- 0 text entities in the file, so nothing in the drawing names
  what any of this is. Every slab-edge LINE carries linetype ByLayer, so whether the line is
  dashed is decided by the LAYER table entry, not the entity. I did NOT read the LAYER table.
  That is the first thing to look at: group code 6 on the LAYER record for each of the three,
  against the LTYPE table, which defines ___HIDDEN, ___DASHED, ___PHANTOM, ___CENTER and Dash.

THE TRAP -- read this before changing a tolerance

  Raising dash-join-gap until the outlines close is the obvious move and may be the wrong one.
  On a structural plan a dashed slab edge frequently means the edge BELOW, or an outline of
  something on another level. Joining it would produce a floor plate that closes cleanly, passes
  every count, imports without complaint, and is not the floor that is there.

  So the question to answer first is not "what gap closes it". It is "what is SLABEDG-2".
  Answer that from the drawing -- the layer's linetype, what the geometry encloses, how it sits
  relative to SLABEDG and SLABEDG-1, whether the same three layers behave this way on sheets
  whose floors DO come out right. Every other C-LEVEL sheet produces a floor; those are the
  control group and they are in the same folder.

  If the honest answer is that SLABEDG-2 is not this level's edge, then say so and the fix is
  elsewhere -- the floor has to come from SLABEDG and SLABEDG-1 and their 46-inch gaps.

BEFORE YOU WRITE ANY JOINING CODE -- THIS IS ALREADY SOLVED IN THIS REPO

  Do not write a new gap-closer. The same assembly already finds a floor plate by a route that
  does not care whether the edge is dashed or broken every eleven inches:

      Kor.Operations.EngineeringTools.Core/PlanGeometry.cs
          MeasureEnclosedArea(luminance, w, h, darkThreshold, sealHairlineGaps: true)
          -- flood-fills the region enclosed by the heaviest closed linework and seals hairline
             gaps on the way. Built for exactly this failure and used by the takeoff engine.
      Kor.Operations.EngineeringTools.Core/SlabAreaReconciler.cs
      Kor.Operations.EngineeringTools.Core/PlateReliability.cs

  The DXF-to-ETABS path calls none of them. It closes outlines from scratch in PlanLoopBuilder
  and is stuck on tolerances, while the plate detection sitting beside it is insensitive to the
  thing it is stuck on. There is also a `vector-plate` / `vector-plate-auto` verb on the CLI, and
  a PDF ingestion path that feeds the same geometry.

  So the first question is not "how do I close these loops". It is: can the plate for this storey
  come from the existing plate detection, with the vector outline used to place and trim it? If it
  can, that is the fix, and it is smaller than anything in the section below. If it genuinely
  cannot -- say why, with what you tried -- then go on to the vector work.

  A caution that cuts the other way: flood fill will happily enclose a region bounded by whatever
  linework is heaviest, including the dashed edge-below if that is what is there. It removes the
  tolerance problem, not the question of WHICH edge is the floor. That question still has to be
  answered.
